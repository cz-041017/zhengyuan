# 配时对齐说明（XHJ-CW-GA-HK3）

## 目标

决策层只发「相位指示」，**不直接控制灯色或配时**。但决策层的相位切换假设
（最小绿 / 最大绿 / 黄灯 / 全红）必须与信号机内部实际配时对齐，否则
P0 等待截止、P1 拥堵压制等硬约束会在信号机侧失效（详见
`docs/decision-algorithm-design.md` §4/§5）。

## 需对齐的参数

| 决策层概念 | 决策层取值来源 | 信号机侧对应项 | 状态 |
|---|---|---|---|
| 最小绿 | `signal.phases[].min_green_s` | 相位最小绿 | 待确认 |
| 最大绿 | `signal.phases[].max_green_s` | 相位最大绿 | 待确认 |
| 黄灯 | 清空时序 `yellow_s` | 黄灯时长 | 待确认 |
| 全红 | 清空时序 `all_red_s` | 全红间隔 | 待确认 |
| P0 截止 | `max_wait_target_s = 130` | 无（决策层内部） | 已定 |

## 风险

- 若信号机侧最小绿 > 决策层假设，决策层的「15s 倒数切换」会被信号机推迟执行。
- 若信号机侧清空时序 ≠ 决策层假设，P0 抢占的预算公式会失准。
- 因此上线前必须从海康《XHJ-CW-GA-HK3 通信协议 / 配置手册》取到实际配时，
  写入 `configs/*.yaml` 的 `signal.phases` 与清空时序，并重跑
  `uv run pytest -q` 与 `timing_analysis` 校验。
